# Predict-fields harness (dev-only)

A dev-only page, `/harness/predict.html`, that runs LFM2.5-VL-450M (onnx-community build, q4f16, transformers.js, WebGPU) once per page, asking for that page's labelled fields with their values and boxes, and scores each against the ground truth. Per field it shows an id (`f001`...), the box verdict (hit or miss) with its IoU, and the value verdict (match, wrong, blank); per page the time; a summary; and the WebGPU adapter. Not part of the built app (`dist/` has no harness, no `.onnx`, no `lfm-vl-models`). It never renders or logs predicted values, transcriptions or filenames.

## Sub-features

- synthetic set: the 8 committed pages in `test-fixtures/predict-fields/` (3 to 5 invented fields each, boxes in `expected.json`), generated by `scripts/make-predict-fixtures.py`
- eval set: one TagStrip annotations-only export plus the source documents, matched by exact filename; only pages with at least one annotated region are scored; the fields asked for on a page are that page's label names; PDFs are rendered like the app does (pdf.js, scale 2), images as they are
- scoring (`src/lib/predict/score.ts`): box hit when IoU (intersection over union) is at least 0.5, per truth region against the same-label prediction with the highest IoU; value verdict from that same prediction (lowercase, letters and digits only; same calendar date; names in either order for labels containing "name")
- "Predictions" select: `model` (default), `truth` (the ground truth replaces the model: every field should be hit and match, no model or GPU needed) and `shifted` (every box moved by half its width: every box should be a miss, values unchanged). This is the scorer check (M1-3).
- results JSON in `window.__predictResults` (`set`, `predictions`, `adapter`, runs with per-page `ms` and per-field `id`, `box`, `iou`, `value`; no text)

## How to get to it

- `http://127.0.0.1:$PORT/harness/predict.html` on the Vite dev server only.
- Precondition for `Predictions = model`: `scripts/fetch-lfm-vl.sh` has been run once in the checkout (about 345 MB into the gitignored `lfm-vl-models/`; a fresh worktree needs it again, or a symlink to the main checkout's folder). Without it the run ends in `data-state=error`.
- Controls: select "Set", select "Predictions", (eval only) file inputs "Export JSON" and "Source documents" (multiple), button "Run". `#status` has `data-state` of `idle`, `loading`, `running`, `done` or `error`; on error `data-error` holds the error class name (never the message). `#adapter` shows the adapter; `#summary` and the table are in `#results`.

## Driving it

```bash
export WORKTREE=/path/to/checkout PORT=5199
S=/home/snaic-darren/projects/tagstrip/.claude/skills/verify-tagstrip/scripts
$S/launch.sh && $S/doctor.sh && $S/pw-install.sh
source $S/env.sh
NODE_PATH=$RUN_DIR/pw/node_modules node $S/drive.mjs --browser chromium --url http://127.0.0.1:$PORT/ \
  --journey predict-harness --set synthetic --evidence "$EVIDENCE_DIR" --check-id M1-1 [--headed] [--block-offsite]
# scorer check, no model:
... --journey predict-harness --set synthetic --predictions truth   (then --predictions shifted)
# eval set (real documents, see the rule below), two runs in one page:
... --journey predict-harness --set eval --eval-export <export.json> --eval-docs <folder> --runs 2 --check-id M1-4
```

`--eval-docs` is searched recursively; the run refuses a folder with duplicate filenames. `--runs N` clicks Run N times in one page (the model loads once). `--headed` opens a visible Chromium (needs WSLg or a display). The driver launches Chromium with `--enable-unsafe-webgpu --enable-features=Vulkan` (override with the `WEBGPU_ARGS` environment variable, space-separated). Timeouts are one hour per run. Exit 0 when every run reached `data-state=done`; it does not judge the decision rule. Evidence: `<check-id>-predict-harness-<set>-chromium.json` (per run: summary, `skipped`, pages with `ms` and per-field verdicts; plus `adapter`), and a `.png` only for `--set synthetic`. `--block-offsite` lists any request that left the origin in `<check-id>-blocked.txt`; M1-2 expects `blockedCount` 0 and the same verdicts as the unblocked run.

## Adapter caveat

Read `adapter` in the evidence. `isFallbackAdapter: true` / architecture `swiftshader` is a software adapter: it does not support shader f16, so the q4f16 model fails there (`GatherBlockQuantized requires f16 but the device does not support it`, run ends `data-state=error`, `data-error=Error`). On the build machine (WSL2, RTX 4070 via `/dev/dxg`) Chromium sees only SwiftShader, headless or headed, with or without the Vulkan flags and `VK_ICD_FILENAMES` for lavapipe: there is no NVIDIA Vulkan driver in WSL, and Chromium's WebGPU on Linux needs Vulkan. So the run needs a machine where Chromium reports a hardware adapter; report the adapter it saw, and do not call a SwiftShader run a WebGPU pass.

## Python reference

Same prompt (`src/lib/predict/prompt.json`), field lists and scoring, PyTorch on the GPU (bfloat16, greedy, 512 new tokens), base model `LiquidAI/LFM2.5-VL-450M` from Hugging Face:

```bash
PY=/home/snaic-darren/projects/lfm-extract-test/.venv/bin/python
$PY -I scripts/predict-reference.py --selftest
$PY -I scripts/predict-reference.py --set synthetic --out <verdicts.json>
$PY -I scripts/predict-reference.py --set eval --export <export.json> --docs <folder> --out <verdicts.json>
```

Pages are the same pixel size as the harness: images as they are, PDFs at pdfium scale 2 resized to round(points x 2). `--out` and stdout hold counts and per-field verdicts by id only. Ids and page order match the harness (export order, pages ascending), so the two outputs line up field by field.

## Real data

The eval set is real applicants' documents (`~/projects/pai-extract/...`). The verifier runs it; builders do not. Evidence holds counts, ids, verdicts, IoUs and times only: no text, no filenames, no screenshots. The harness, driver and Python reference already withhold them; do not add logging that would not.

## Gotchas

- First `Run` includes model load and an untimed warm-up on the first page; load time is not in the per-page times.
- Input labels are aria-labels on the controls; match with `exact`.
- transformers.js 4.3.1 skips its local-file check when `localModelPath` is an absolute http(s) URL, so the harness uses an origin-relative path; do not "tidy" it.
